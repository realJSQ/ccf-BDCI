# 根据开发负结果设计下一轮研究

沿用用户已批准的自动选题、CPU + API 和真实证据约束。本步目标是让研究 Agent 提出可实施的方法改进与前瞻验证，而非重复基础模型能力测试；旧论文、原始失败和无收益结果保留。

输入是经过CPU复验的严格/事后结果、冻结协议、已核对版本的一手文献及其局限。设计者需要比较至少两种可行路线，自主选择或拒绝，说明具体干预、强基线、独立评分边界、可证伪主张和任务划分。审查者只评当前设计，绑定其哈希，并为阻断意见引用当前字段原文。

工程上复用原生JiuwenSwarm两角色调用与持久BudgetRail。新设计campaign最多2次模型请求，输出上限4500 tokens/请求，已知usage达到24000后阻止下次准入；阈值不是硬费用上限。旧campaign不重置。默认离线夹具只验证编排，不能产生研究结论。

设计可提出最多36次实验请求的方案，但本步不执行这些实验。是否实施需检查具体方案的预算算式、对照公平性、数据划分和计算逻辑。handoff.execution_enabled始终为false，模型审查通过不等于科学认证。没有独立验证的数据不能标为独立验证；换数值种子不能伪装新任务结构。

完成本步的证据是：入口与契约测试、原生离线编排、至多两次真实设计/审查响应和usage、绑定当前稿的handoff，以及开发助手对剩余语义问题的记录。完整竞赛目标仍需后续实施、验证、统一流程、论文、外审Token与官方贡献PR，不以本设计步骤替代。
