# 恢复研究的实验后编排

这是已批准的 submission-workflow-design 中跨阶段输入、写作与交付部分的实施细化，不替代自动选题到最终参赛作品的完整目标。当前真实实验仍只有六个开发实例，不能把软件连通性当独立科学验证。

## 选择与范围

继续手动调用各脚本容易将新的写作输入与旧的打包输入混用；直接重写全部研究阶段会重复原生框架和预算逻辑。因此复用现有入口，增加持久化协调器，从明确指定的已完成兼容实验开始。选题、方法设计与新实验不在本次自动调度范围内，不能宣称全流程已完成。

命令必须指定实验和输出目录。可指定已保存论文，或让原生 writer/reviewer/reviser 生成；后者默认离线脚本模型，只有显式 live 才使用现有研究预算。不开新 campaign、不清空账本、不自动重试。离线论文和包明确标为集成验证，不能计入真实研究或外审作品。

## 阶段与数据

1. 用冻结实现复验实验与事后分析，保存证据摘要哈希。
2. 验证指定存稿，或向原生写作入口传入同一实验路径和预先确定的输出目录；固定论文、证据与PDF哈希。
3. 打包器接收同一实验和论文目录，包内实验路径写入manifest；资源报告只使用可追溯usage，搬迁副本不重复计费。
4. 将ZIP解包到临时目录，用包内校验入口重新检查，并记录ZIP哈希和最终状态。

协调器不修改 latest 论文指针。其状态文件使用原子替换，并持有排他锁防止两个恢复进程同时调度。独立子进程运行原生写作，其stdout/stderr留本地；阶段错误只报告类型，原始运行记录保留。

## 恢复和失败

输入内容变化或文件缺失时拒绝继续，不回退历史默认目录。恢复已完成阶段会重新校验输入/论文/ZIP哈希，不能只相信保存的 completed 字段。写作中断后若已保存完整三角色原始响应和usage，可使用原写作入口零API resume；否则停止并指向原运行目录，禁止为追求流程成功而重发。完成的写作不会再次请求模型；打包输出不覆盖，已生成的完整包须验证后才能采纳。

## 验证

单元测试覆盖状态不明的写作禁止重发、输入变化拒绝、存稿内容绑定、已完成恢复与ZIP损坏。实际运行覆盖真实历史实验与存稿的一条零API交付链，以及同一真实实验输入的原生离线写作/编译/打包链。离线产物不得覆盖真实论文指针。选题、外审、官方贡献PR与正式提交继续单独验收。

设计自审：明确了离线与真实边界、持久化恢复、资源口径和当前研究协议范围；没有引入新科学结果、隐式预算或外部提交动作。
