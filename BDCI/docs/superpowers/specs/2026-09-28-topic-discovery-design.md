# 自动选题阶段设计

用户已确认由 Agent 提出和筛选论文课题，并要求继续推进。本阶段承接已通过的实验/写作框架验证，不把固定排程实验当成科研选题。

采用原生 SwarmFlow + TeamWorkerBackend 三角色流水线：检索规划者生成检索词；固定检索客户端获取公开论文元数据与摘要；提案者提出最多三个假设及对照实验；针对候选的相近工作再次检索；独立批评者判断候选是否值得预实验；确定性门禁校验引用、预算与评审结果，输出预实验交接文件。

备选路径：单提示直接生成课题最省调用但依据薄弱；自主长循环成本不确定。本轮选择三次调用、两轮检索的流程，验证模块接口与可追溯性后再扩展。

研究范围为 Agent 技术；约束为当前电脑、外部模型 API、不训练大模型、不要求 GPU。用户无需指定具体论文题目。初筛依赖摘要，不能声称完成全文综述或证明新颖性。合格状态仅为 eligible_for_pilot，最终课题须经实际预实验确认；无合格候选时输出 needs_revision，不杜撰成功。预实验交接包含假设、基线、指标、数据、步骤、资源上限，本阶段不执行模型生成的任意代码。

检索数据是非可信数据，不是执行指令。固定 HTTPS 端点、超时、查询/结果/响应体上限，无自动重试。所有引用必须存在于本轮已保存的来源表。离线虚构文献单独标 synthetic，不允许用于真实预实验或论文。

新增 JiuwenSwarm ResearchBudgetRail，限制实际模型调用次数与输入字符数，持久化 admission 与 usage，超限以取消信号阻断框架重试。API 客户端和工作流重试均关闭。新的 topic-v1 预算独立于已耗尽的 smoke 预算：最多三次请求，每次最大2200输出token；累计实际usage到20000后停止，后反馈阈值可能被最后一次请求跨过，并非预付费硬上限。检索最多四次，每次最多五篇。工作流总超时360秒。下一轮不得自动重置预算。

验证：纯模块单测覆盖错误引用、缺失摘要、超预算、否决、虚构来源隔离及调用阻断；真实框架离线端到端；一次受限真实模型/检索实跑。保留事件、请求计数、usage、来源与哈希、候选、评审、决策、耗时，提供JSON和Markdown交接。旧smoke脚本保持可复现，不修改Git配置、不提交推送。

实施顺序：来源客户端与候选契约并行；预算Rail；角色文件及工作流；离线/负例验证；有界实跑；交接与说明。后续工作：预实验执行器、依据结果修订/换题、全文检索、完整实验与论文写作。
