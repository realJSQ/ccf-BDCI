# 自动修订选题的执行范围

本阶段沿用用户已确认的原生框架与自动选题流程，执行持续目标“尝试改进方法，完善整个流程，最终生成一份可提交的作品”。不将未回答的路线偏好问题当作额外许可要求，也不代替 Agent 指定最终题目。writing-plans 技能不在当前可用目录中，因此用本地执行清单记录步骤。

1. 保存四篇已阅读官方 arXiv 章节的来源卡，注明由开发助手提供的检索起点、阅读范围和未独立复现边界。来源卡不是自动文献综述，也不是新颖性证明。
2. 实现三个原生 SwarmFlow 角色：proposer 给出两候选和后续检索词，critic 对两个候选逐一批评，refiner 仅修订未被否决的候选或拒绝继续。
3. 本地契约拒绝虚构引用、跳过批评、超出资源计划和宣称已证明新颖性；结构覆盖不能认证语义正确。
4. 软件测试与原生离线流程验证通过后，执行一次真实三角色修订。新 campaign research-v2 总上限24次请求、每次输出3200 tokens、usage达到100000后停止后续请求；本入口正常执行只发3次请求，不启动实验，不清除旧账本。
5. 检查真实候选和批评，执行 Agent 提出的定向检索；必要时反驳或修订候选。完成具体近邻核对后，才冻结实验问题、强基线、数据划分及独立评分方法。

当前只实现开发交接，不将它命名为最终选题完成。最终论文、正式实验、外部审稿和官方 PR 仍是完整目标的必要部分。
