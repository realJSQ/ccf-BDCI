# 协议修订请求与后续授权

自动审批最初拒绝了请求。用户随后回复“也不用这样过分限制token，正常测试就可以”，并明确“不用限制token数”，已授权按正常研究测试推进。实际执行了1次设计与2次审查（其中1次因服务默认长度截断而重试），共47,220 tokens，没有运行新实验。最新状态见 `request.json` 及其列出的真实运行目录；初始准备文件保留用于追溯，不能当作实际最新提示。

`prompt_designer.txt` 是已生成的实际设计提示；`context.json` 包含既有实验结果、公开论文摘录与失败诊断。`auditor-instructions.txt` 为审查角色规则，实际审查还会收到第一步新设计及其哈希。`request.json` 列出服务地址、模型、两次请求上限和这些文件的哈希。密钥不在提示中；若获准请求，将只作为该服务的认证凭据读取。

`campaign.json` 与初始输入来源记录来自原生离线验证；离线响应为decline/reject夹具。真实修订仍记录在独立账本，没有清空旧记录。取消项目token阈值后，省略max_tokens触发了服务默认8192输出截断；最终按 `/models` 返回的393216最大输出容量配置，不再人为压低长度。该审查完整返回reject。累计真实模型调用现为47次、192,805 tokens。
