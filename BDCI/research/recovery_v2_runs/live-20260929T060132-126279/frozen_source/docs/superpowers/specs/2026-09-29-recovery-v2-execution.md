# 恢复机制修正与前瞻实验

沿用已批准的自动科研及恢复研究路线。本规范是开发助手对 Agent 提案中已复现错误的明确修正，不声称由模型独立完成。保留旧论文、负结果、失败提案与全部调用记录。用户已取消人为 token 限制；新调用只受服务容量和预先确定的实验设计约束。

## 选择与主张

比较三条路线：只修复旧演算不能支持新验证；纯整数 DAG 适合工程测试但削弱已有领域语义；采用现有三领域任务的分组计算结构，修正实际依赖传播并加入确定性基线，最直接检验此前 Agent 提出的恢复问题。因此选择第三条。

研究对象是固定输入下的恢复计划及执行策略，不是基础模型算术能力。可靠实际依赖图来自已知工具定义，所有策略以及模型规划者均可见。它不是从损坏声明中自动学出的图，不能声称解决未知依赖发现。

E 使用从变化源开始的实际图前向闭包，加上模型请求节点，按实际拓扑执行。G 完全不用模型请求，只执行同一实际图闭包。E 的工具数不可能小于 G，因此不提出“E 优于传统闭包算法”的主张。主要描述 E 相对 A 的正确完成率差与调用开销；同时报告 G、完整重放 F 以及声明图消融 D。如果 A=E，应报告无额外保护收益。

## 数据与划分

保留 tabular（金额乘地区费率）、retrieval（每实体最新记录按启用标志聚合）、classification（预测与标签比较）语义。评分使用既有独立 `replay_reference.py`，直接读取完整源行，不读取声明图、执行缓存或策略门禁。执行器与 oracle 同作者，但不同实现。

工具图有两个源 main/aux。分片数为 1 时直接汇总；大于 1 时先按键的 UTF-8 字节和模分片数分组，各分片汇总，再合并互不重叠的键。combine 进行领域计算，report 复制最终结构。所有分片工具均计一次调用，包括空分片；不以调用数等同实际计算费用。

- 开发图：(main, aux) 分片数 (1,1)、(2,1)、(1,2)。每领域每结构一实例，共 9。
- 保留图：(2,2)、(3,2)、(2,3)。每领域每结构一实例，共 9。生成规则和源数据在模型请求前冻结；不依据其模型结果调方法。
- 每实例 clean、aux_update、joint_update、incomplete_lineage 四个场景。最后一种与 aux_update 数据相同，只从声明图删去 aux 汇总到 combine 的边，工具实际读图不变。
- 开发集仅 CPU 工程验证，不产生模型实验样本。正式保留集拟 9×4=36 份模型计划；每份计划复放 A/D/E/F 四策略，另每场景执行 G。配对统计以 9 个基础实例为单位，36 个场景不当作独立样本；这仍是小规模、自建、结构保留集。

## 执行契约

模型输出 JSON actions，每项 rerun 含节点，最后 emit 或 refuse；不增加自由文本长度阈值。非法 JSON/动作/缺终止必须记录，不能偷偷补 emit。A 保持请求顺序和重复；D/E 保留请求节点并加入声明/实际闭包，去重拓扑执行；F 有变化时完整重放，clean 时仅去重模型请求。A/D/E/F 共同尊重显式拒绝和结构无效计划。G 没有模型计划，单独列为确定性策略，不因模型拒绝而失效。

工具预算每场景为实际节点数两倍，使完整重放可完成；模型计划可在该预算内请求重复节点。没有瞬时故障，不保留无意义的重试收益主张。新鲜度诊断记录父产物哈希与源版本；最终数值正确性与来源新鲜度分别报告，不能混为一个正确标签。

输入包括节点与算子说明、实际/声明图、源版本和变化源、旧缓存、工具预算；不含 oracle 答案、场景标签、故障位置或评分结果。实际图与声明图的差异本身可观察，是此信息条件的一部分。G 不使用 oracle。各策略读取相同公开输入的哈希必须相等。

## 验证与后续编排

先用开发集和旧失败反例验证执行器、oracle 分离、前向恢复、图消融、保留缓存、模型拒绝及资源计数；工程 fixture 不计入研究结果。旧历史模块保持不变。

下一步将固定规范、源码、源数据和提示快照交给原生 JiuwenSwarm 规划流程，冻结后执行保留集，记录每次请求与全部失败；未运行前不宣称研究改进成立。模型调用按现有授权执行，无 token 停止阈值、无字符截断，保留未知请求防重放与 usage。分析需公开每个基础实例的配对结果，不以筛选显著性或追加样本追求正结果。最后接写作、审稿、PDF、贡献与具名提交包；此规范和开发验证不是最终完成状态。
